# ИАиВД: самостоятельная работа к занятию 3.2

Трек «ML-инжиниринг». Источник задания: опорный конспект 3.1 «Метрики качества классификации», раздел 8.

## Задание 1. Мини-расчет нашего проекта

### Постановка

Модель-советчик получает новую карточку SIEM и оценивает, является ли она реальным инцидентом. Итоговый вердикт выносит аналитик (Human-in-the-loop); модель только ранжирует очередь и подсвечивает карточки, которые нельзя закрыть как ложное срабатывание.

### Положительный класс

**Класс 1 — реальный инцидент:** вердикт аналитика «Решён», «Не решён», «Закрыт по совокупности инцидентов» или «Закрыт из родительской атаки».
**Класс 0 — ложное срабатывание:** вердикт «False Positive».
Карточки с вердиктами «Не указан» (54 870) и «Дубликат» (5 819) в разметку не входят: для них нет эталонного факта y.

| Класс | Карточек | Доля |
|---|---|---|
| 1 — реальный инцидент | 28 931 | 16,1 % |
| 0 — ложное срабатывание | 150 675 | 83,9 % |
| Всего размечено | 179 606 | 100 % |

Положительным выбран именно инцидент, а не ложное срабатывание, хотя FP в потоке больше и «по умолчанию» напрашивается частый класс. Цель SOC — не пропустить атаку, поэтому метрики должны считаться по редкому классу, ошибка на котором стоит дороже всего. Из таблицы видна и ловушка доли правильных ответов: правило «всегда False Positive» наберет 83,9 % при нулевой полноте.

### Две главные метрики

1. **Полнота (Recall) по классу «инцидент»:** TP / (TP + FN), доля реальных атак, которые модель отметила.
2. **Точность (Precision) по классу «инцидент»:** TP / (TP + FP), доля отмеченных карточек, которые действительно оказались инцидентами.

**Обоснование.** Непростительная ошибка для нас — FN: пропущенный инцидент, который модель пометила как ложное срабатывание и который ушел вниз очереди или был закрыт без разбора. Его цена — ущерб от атаки, поэтому полнота стоит первой и задает нижнюю границу порога (например, не ниже 90 %). Точность — вторая метрика: она переводит ложные тревоги (FP) во время аналитиков L1, которые и сейчас разбирают почти 84 % пустых карточек. Среди режимов, где полнота не ниже заданной границы, выбираем порог с максимальной точностью. Долю правильных ответов и ROC-AUC как главные метрики не берем: при доле инцидентов 16 % первая обманчива, а вторая не видит цену FP и не выбирает порог.

### Наблюдение из данных, важное для матрицы стоимости

Доля реальных инцидентов заметно различается по срезам: в группе L1 — 15,4 %, в L2 — 59,7 %, в ГИБ — 96,9 %. У карточек с критичностью «Критическая» она всего 3,6 % (38 из 1 057) — ниже, чем у «Средней» (16,3 %). Поле «Критичность» из правила корреляции не заменяет оценку модели, и метрики стоит проверять отдельно по срезам, а не только в среднем по потоку.

## Задание 2. F-мера с параметром β

Формула:

Fβ = (1 + β²) · P · R / (β² · P + R)

β показывает, во сколько раз полнота важнее точности: при β = 1 это обычная F1, при β > 1 акцент на безопасности (полноте), при β < 1 — на экономии времени аналитиков (точности).

Пересчет примера из конспекта (рабочая точка τ = 0,18: P = 34,2 %, R = 79,9 %):

| Метрика | Расчет | Значение |
|---|---|---|
| F1 (β = 1) | 2 · 0,342 · 0,799 / (0,342 + 0,799) = 0,5465 / 1,141 | ≈ 47,9 % |
| F2 (β = 2) | 5 · 0,342 · 0,799 / (4 · 0,342 + 0,799) = 1,3663 / 2,167 | ≈ 63,0 % |
| F0,5 (β = 0,5) | 1,25 · 0,342 · 0,799 / (0,25 · 0,342 + 0,799) = 0,3416 / 0,8845 | ≈ 38,6 % |

**Как β смещает баланс (ответ для устного разбора).**
- β² стоит множителем при точности в знаменателе. При β > 1 вклад точности в знаменатель растет, и метрика определяется в основном полнотой. Поэтому F2 «прощает» низкую точность 34,2 % и поднимается до 63 %, ближе к полноте 79,9 %.
- При β < 1 вес точности в знаменателе мал, и метрика тянется к точности. Поэтому F0,5 = 38,6 % — ближе к 34,2 %.
- При β = 1 веса равны; гармоническое среднее тянется к меньшей из двух метрик (47,9 % — ближе к точности, чем среднее арифметическое 57 %).
- Предельные случаи: при β → ∞ Fβ → R, при β → 0 Fβ → P.
- Один и тот же режим получает три разные оценки: метрика не «правильная» сама по себе, β выбирает заказчик. Связь со стоимостью ошибок: β = √(цена FN / цена FP). Например, если пропуск в 4 раза дороже ложной тревоги, то β = 2.

**Для нашего проекта** ориентир — F2 или выше: пропуск инцидента дороже ложной тревоги, что соответствует выбору полноты первой метрикой в задании 1. Точное значение β получим из матрицы стоимости ошибок на занятии 3.2.
